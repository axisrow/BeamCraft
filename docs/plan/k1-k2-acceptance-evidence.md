# K1 and K2 acceptance evidence

This is the verification deliverable for fork issue #11 (upstream #125), against the verified
fork integration commit `dae17846453b0e18d58b9fad55f3acbd6c22100d`. It does not change an owner gate
claim or the frozen F04/F06 contracts. K0 was accepted by the owner on 2026-10-20 and is not
re-decided by this report.

## Owner decision (2026-10-24)

The owner accepted K1 and K2 as passed on 2026-10-24 ([decisions](decisions.md)); `ROADMAP.md`
records both gates as passed. The verdict below is the evidence as recorded on 2026-10-23. Since
then:

- #174 fixed the K1 plate contour, body frame and unsupported-draft gaps that #171 tracked:
  `f04_cases.rs` declares no contour-admission or wrong-code deviation any more.
- #222 made members accept a rigid placement rotation and refuse negative widths with
  `INVALID_ARGUMENT`: `f06_member_cases.rs` no longer carries the POS-12, NEG-52 or NEG-53
  deviation.

Accepted limits, still asserted as such by the fixture adapters so CI notices a change:

- F06-POS-11: a rotated plate placement is `UNSUPPORTED_GEOMETRY` (`f06_cases.rs`).
- The public face table returns `plate:f.x0` where the fixture names the role `x0`.
- F04 cases that need a raw envelope decoder, workspace preconditions or a trusted actor
  context are inventoried and not run.
- F06 feature lookup, invalidation, delivery, hostile blob and query/injection adapters are not
  run as whole contract cases, and the ordinary OpenUSD check is a Linux sample, not an OS matrix.

## Verdict

| Gate | Evidence verdict | Why |
|---|---|---|
| K1 | Failed contract acceptance; supported runtime scenario passes | Rotated placement and plate contours outside the supported plane disagree with F04/F06; exact face identity strings also disagree. Missing protocol assertions remain not run. |
| K2 | Failed contract acceptance; supported runtime scenarios pass | F06-POS-12 expects a rotated member in world space; the engine returns `UNSUPPORTED_GEOMETRY`. NEG-52/53 expect `INVALID_ARGUMENT` for negative widths; the engine returns `LIMIT_EXCEEDED`. Remaining field/protocol and persistence limitations below are not counted as passes. |

The deviations are bugs or unsupported contract requirements, not successful acceptance. The
fixture adapters deliberately assert the known observed deviations so CI detects changes to them;
a green Cargo process therefore does not imply a passed gate. Upstream #171 already tracks the
K1 contour, placement and face-table gaps; its draft implementation #174 must be evaluated after
integration, not credited to this base. New fork issues [#68](https://github.com/axisrow/BeamCraft/issues/68)
and [#69](https://github.com/axisrow/BeamCraft/issues/69) track the reproduced K2 rotation and negative
dimension deviations respectively. The negative-width error also reproduces through real
`define-profile` commands with widths `-3000000` and `-1e308`, height `300`: both return exit 2 /
`LIMIT_EXCEEDED` instead of the required `INVALID_ARGUMENT`.

## Reproduce

```sh
cargo test --locked -p beamcraft-cli --test f04_cases --test f06_cases --test f06_member_cases -- --nocapture
cargo test --locked -p beamcraft-cli --test plate --test recovery --test history_compact --test prim_naming --test independent_reader
cargo test --locked -p beamcraft-cli --test members --test copy --test workspace --test undo
```

These execute the actual frozen JSON fixtures, public engine functions and real CLI processes.
No fixture expectation is generated by a production geometry function. Coordinates compare with
`0.001 mm + 1e-6 * abs(expected)`, quantities with relative `1e-6`, and dimensionless frame values
with relative `1e-6` (absolute `1e-6` at zero), following the fixture's comparison policy. Identities,
counts, digests, codes and statuses compare exactly.

## K1 inventory

The existing [K1 inventory](../design/k1-contract-acceptance.md) enumerates all 69 F04 logical
cases, seven raw envelopes and all 112 F06 cases, including every skip and partial assertion.
Its recorded run used an older integration point and the former Python oracle. The current
fixture adapters are rerun by the commands above; use `independent_reader.rs` and the Rust
`beamcraft-usd-oracle` for the current independent-reader evidence. This in-repository reader is
independent of the layer engine, but is not the ordinary OpenUSD SDK itself.

- F04 plate admission: 33 matching projections, four explicit deviations, five context skips.
  The remaining 27 logical cases and seven raw envelopes are inventoried, not asserted by that
  adapter. In particular, no raw F04 command-envelope decoder is invented for this report.
- F06 plate adapter: 21 driven cases. POS-02 passes its complete byte/digest projection. The
  remaining projected fields, non-planar/rotated deviations, face-table string disagreement and
  unexecuted protocol fields retain their explicit dispositions.
- K1 runtime evidence: `plate.rs` covers independent complete revisions, fresh-process reopen,
  closed shells, volume, replay, refusal, concurrent writers and killed commits. `recovery.rs`
  checks interrupted commits, torn records and contradictory journals; `history_compact.rs`
  checks retained content and corrupted blobs; `prim_naming.rs` checks the current full identities
  and links; `independent_reader.rs` reads saved layers without using the layer engine.

## K2 fixture inventory

`f06_member_cases.rs` now drives all 30 member/mixed cases previously assigned to K2 by the K1
inventory. Every member or mixed fixture case is asserted exactly once, and the driver refuses a
member or mixed fixture case that its case list does not name, so additions or removals require an
explicit inventory change. Every result is printed as `PARTIAL` or `DEVIATION`, not a full contract pass.

| F06 cases (prefix omitted) | Assertions and limits |
|---|---|
| POS-04, 05, 06, 07, 08 | Exact counts; fixture vertices, available frame components, local bounds, axis length and quantities; independent mesh area, signed volume, Euler count and opposite shared-edge incidences. POS-07 also checks fixture mass. No persisted-state or protocol claim. |
| POS-09, 10, 41, 42, 46 | Frame components available in the fixture are recovered from the actual emitted vertices and compared; mesh closure/volume are independently checked. Internal branch labels, predicate certificates and every explanatory field are not asserted. |
| POS-12 | Explicit deviation: expected world rotation, observed `UNSUPPORTED_GEOMETRY`; no world mesh is returned or claimed. |
| POS-13 | Fixture axis length, volume, mesh surface area, unknown mass without density, and current 480 kg mass at fixture density. Bounds-status and protocol fields are not asserted. |
| POS-14 | Both fixture bodies execute: the thin plate's two volume units and the short member's axis length and volume match. No blob/protocol claim. |
| POS-15 | Inclusive large section, fixture volume in both units and independent mesh closure/volume. No saved-stage budget claim. |
| POS-50, 51, 52 | Available rolled frame components and bounds, volumes/areas where specified, and independent closed mesh. Keys and stable role-identity comparisons remain not run. |
| POS-57, 58 | Accepted geometry at the scaled boundaries, unchanged authored input, independent closed mesh/volume. Internal scale/floor values are not exposed and not asserted. |
| NEG-04, 05, 06, 07, 43, 44, 47, 48, 51 | Exact F04 refusal code from the engine, with no success value. Diagnostic stage/code and absence of a persisted revision are not asserted by this pure adapter. |
| NEG-52, 53 | Explicit deviations: the frozen expected code remains `INVALID_ARGUMENT`; actual code is `LIMIT_EXCEEDED`. No invalid profile was accepted. |

The separate `members.rs` integration tests check saved/reopened beams and columns, quantities,
pinned definitions, rolls, argument refusal, operation replay, duplicates and the one-cubic-metre
regression. `copy.rs` checks independent copies and unchanged sources; `workspace.rs` checks draft
isolation, fast-forward publication, restart/resume and conflicting heads; `undo.rs` checks local
undo/redo, move/delete restoration and interrupted steps. The independent reader checks the
saved beam and column against external closed-form expectations.

F04 `CreateStraightMember` cases remain inventoried by the existing F04 adapter, rather than
being silently credited from differently shaped CLI tests. F06 feature lookup, invalidation,
delivery, hostile blob and query/injection adapters listed in the K1 inventory also remain not
run as whole contract cases. Ordinary OpenUSD interoperability across the supported OS matrix
and owner gate sign-off remain separate acceptance evidence.

## Recorded run

Executed on 2026-10-23 (Asia/Shanghai), Linux x86_64, Rust 1.99.1. All five fixture-driver tests
passed their explicit projections/inventories: two F04, two K1 F06 and one K2 F06 driver. The new
K2 driver executed 30 cases: 27 partial projections and the three deviations above. All 25
targeted CLI/runtime/independent-reader tests passed. Formatting and workspace clippy with
`-D warnings` passed. Passing these tests does not change either failed contract verdict.

As an additional external check, installed ordinary OpenUSD 0.26.5 opened the five-part Q01
frame generated by fork PR #67 using the same integration code. Manifest layers were materialized
under their verified SHA-256 names. OpenUSD read five meshes, Z-up and 0.001 metres per unit;
an independent triangle sum gave volumes of 5,000,000; 5,000,000; 4,750,000; 396,000; and
396,000 mm³ within relative `1e-6`. Its compliance checker reported empty errors, failed checks
and model warnings (the SDK separately warns that this checker API is deprecated). This is a
Linux sample, not an OS matrix, the unsupported placements, or a full gate pass. The SDK was
already installed in the test environment; no SDK or Python dependency is added to the project.
